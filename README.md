# رِفد — مشروع استوديو خدمات رقمية

واجهة عربية متجاوبة لمتجر خدمات رقمية صغير ولوحة تشغيل محلية. الهدف اختبار عرض خدمات رقمية تُنفّذ بعد الطلب دون شراء مخزون أو دفع تكلفة مسبقة.

## التشغيل

افتح `index.html` مباشرة في متصفح حديث. لا توجد مكتبات أو اشتراكات مطلوبة. الخدمات والطلبات تُحفظ في `localStorage` على الجهاز والمتصفح نفسه فقط.

## ما يعمل حاليًا

- متجر خدمات قابل للتصفية بحسب النوع.
- نموذج طلب خدمة أو طلب خاص.
- لوحة داخلية لإدارة الطلبات وحالاتها والخدمات.
- مسودة عرض بيع أولية بقوالب محلية، قابلة للنسخ والمراجعة.
- تصميم متجاوب للهاتف والكمبيوتر.

## ما يحتاج تفعيلًا قبل البيع الفعلي

1. **تأكيد الخدمة:** اختاري خدمة تستطيعين تسليمها بنفسك. الأسعار ومدد التسليم افتراضية للاختبار، وليست دراسة سوق.
2. **قناة استقبال الطلبات:** اربطي النموذج ببريد أو نموذج مستضاف أو قاعدة بيانات. الإرسال الحالي يُحفظ محليًا على جهاز الزائر ولا يصل إليك.
3. **الدفع:** اختاري مزود دفع مناسبًا وافتحي حسابًا باسمك/نشاطك. لا توجد معالجة دفع داخل هذا المشروع.
4. **الذكاء الاصطناعي:** زر المساعد يستخدم قالبًا محليًا ولا يستدعي نموذجًا. للذكاء الحقيقي يلزم API ومفتاح سري على خادم وسيط؛ لا تضعي المفاتيح في `app.js` أو في الموقع العام.
5. **النشر:** ارفعي ملفات المشروع إلى استضافة ثابتة. النطاق الخاص والاستضافة وبعض بوابات الدفع قد تكون مدفوعة؛ ليس هناك تكلفة تلقائية مخفية في المشروع.
6. **التنظيم النظامي:** تحققي من متطلبات ممارسة النشاط والتجارة الإلكترونية والإفصاح وسياسات الاسترجاع والخصوصية قبل استقبال العملاء، بحسب وضعك ونوع النشاط.

## نموذج العمل

خدمة رقمية محددة النطاق تُنتج بعد الاتفاق والطلب؛ لا مخزون ولا شراء تلقائي. استخدمي وصولًا عضويًا للمبيعات في البداية: عينات من عملك، منشورات تعريفية، ومراسلات مهنية غير مزعجة. لا تعدي بتسليم أو نتيجة قبل التأكد من قدرتك عليها. ارفضي الطلبات الأكاديمية التي تعني أداء واجب أو اختبار بدل الطالب، واستخدمي الذكاء الاصطناعي للمسودات مع مراجعة بشرية.

## تخصيص سريع

- غيّري قائمة الخدمات والأسعار من قسم الخدمات في اللوحة.
- عدّلي نصوص المتجر داخل `index.html`.
- خصصي الألوان والخطوط في أعلى `styles.css`.
- عدّلي الخدمات الأولية في `defaults` داخل `app.js`.
